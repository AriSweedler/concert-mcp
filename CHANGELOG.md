# Changelog

All notable changes to this project are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project uses [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- The invite to-do (bead beads-hmxw): a show with a calendar event and a Partiful page that starts more than 30 days from now gets one Google Task, `invite people to <artist>`, due on the show's day less 30 days, its notes the Partiful page, the calendar event's link and `Created by github.com/AriSweedler/concert-mcp`. Whichever step completes the pair makes it (`concert_add` with a `tickets:` line, `tickets_add` and `/tickets` when the link comes later), and its reply gains one line, `To-do: [invite people to <artist>](<task link>)`. The concert's record keeps the task (`todo`), so a repeat makes none, and `concert-mcp concerts` lists it as the `invite to-do` expression. A failed call fails nothing: the reply says `To-do not made: <why>.` and the next step that finds the pair complete tries again. `event_delete` of the show deletes its to-do unless it is completed. Plain events, movies, shows 30 days away or less and shows without a page get none. `CONCERT_MCP_TASK_LIST` (default `@default`) names the list; `TasksApi` and `GwsTasks` (gws `tasks tasks insert`, `get`, `delete`); the `tasks-auth` healthcheck row reads the list under `--probe`. The Google login now asks for both scopes: `gws auth login -s calendar,tasks`.
- A guess at where a show's setlist will be (bead beads-mvfi): when a concert is added, `concert_add` reads the artist's most recent setlist.fm page (usually an earlier night of the tour), says `possible setlist.fm link` in its reply with those three words linked, and keeps the guess in the concert's record (`setlist_guess`), apart from the page the user gives. Nothing acts on a guess: no playlist, no link on the calendar event or the invite, and `/setlist` with no link still answers that none has been given. No page, no key or a refusal: no line, and the concert is added all the same. Once the event carries the show's own page there is no guess.
- `/setlist <link>`, a chat command (bead beads-7k4): typed in a show's topic after the show, it runs `concert-mcp setlist-playlist --url=<link> --topic=<chat>:<thread>`. The setlist flow now writes `setlist.fm: <page>` next to `Setlist playlist: <url>` on the calendar event, and a show that has a Partiful invite gets both links on its page, added to whatever the page already links to (`PartifulApi.event_links` and `set_links`, a Firestore commit as the site's editor makes it). `concert-mcp setlist-playlist --topic`. With no link, `/setlist` (and `setlist_playlist` in a topic) reads the page the show's event already carries and tops the playlist up; a show with no page yet answers `You haven't given this show's setlist yet. Send /setlist <link to its setlist.fm page>.`, and nothing is searched for. A different page for the same show is a correction (an earlier night of the tour stood in until the show's own page existed): it takes the earlier page's place on the event and on the invite, and the playlist is rebuilt from it, in its order, with nothing of the old page left (`SpotifyApi.remove_items`; the reply says `(rebuilt from this page)`).
- `/tickets <link>`, a chat command (bead beads-1xu): `openclaw/concert-commands` is an OpenClaw plugin that registers the one command and runs `concert-mcp tickets --link=<link> --topic=<chat>:<thread>` for the topic it was typed in, so a ticket link needs no model turn. `concert-mcp tickets --topic` names the Telegram topic that owns the show; a named topic with no show answers that there is no event yet.
- A record per concert (bead beads-p7a): `<state_dir>/concerts/<YYYY-MM-DD>-<artist>.json`, a local cache of the show's facts and of the expressions made of it. `concert_add` writes it, `CachedCalendar` keeps it in step with every later write or read of the show's calendar event, and `tickets_add` finds the show in it instead of searching the calendar. `text/records.py` says from a record alone what is known, what an invite would hold, and whether each expression is made, can be made, needs the ticket link or is out of date. `concert-mcp concerts` lists the records; `CONCERT_MCP_CONCERTS_DIR` moves them. `StateStore.names`.
- Partiful invites (bead beads-pyy): a concert whose ticket link is known is expressed as a public Partiful event, and no model decides it. `concert_add` finds a `tickets: <URL>` line in the text it is given; `tickets_add` (CLI `concert-mcp tickets`), the eleventh tool, takes the link when it arrives later. The calendar event gains `Tickets: <url>` and `Partiful: <url>`, both kept across updates; the invite is `Concert: <artist> at <venue> <m/d>` with the doors and show times, the venue as a Maps place, the cover of the artist's newest album as its poster (`SpotifyApi.artist_albums`), and the link fields `Tickets` and `<Artist> songs I like`, plus `setlist.fm` and `Setlist playlist` once the show's setlist is given (beads-7c5, beads-7k4). Partiful has no API, so `adapters/partiful_http.py` makes the calls its site makes. `partiful_login` (CLI `concert-mcp partiful-login`), the twelfth tool, logs in by a texted code through the chat: `CONCERT_MCP_PARTIFUL_PHONE` names the number, `<config_dir>/partiful.json` holds the session, and a dead session replies `Partiful is signed out` with a new code already on its way. Healthcheck rows `partiful-session` and `partiful-auth`.
- A venue registry (`<config_dir>/venues.json`): every concert's venue is looked up once (Google Places when a key is stored, else OpenStreetMap's Nominatim, else the address block printed on the ticket) and kept with its Maps-form address, website, coordinates and the dates visited. The event's `location` becomes the form Google Calendar turns into a place card, the description gains `Venue: <website>` when known, and a second show at the same venue needs no lookup. `concert-mcp venues`, `venues lookup --name`, `venues auth`; the `places-key` healthcheck row is `SKIP` without a key; `CONCERT_MCP_VENUE_LOOKUP=0` turns the network lookups off.
- A `Headliner: <title>` description line before the `Opener:` lines when a concert has openers.
- `setlist_playlist` (CLI `setlist-playlist`), the eighth tool: a pasted setlist.fm link (or artist and date) becomes the Spotify playlist of the show's setlist, in setlist.fm order, named `YYYY-MM-DD | Artist`, each song found by `track:<name> artist:<artist>` search; a repeat call tops it up with the songs it lacks and the reply names the songs not on Spotify. The teaser playlist of the same name is told apart by its description (`Setlist:` vs `Teaser for`), the two descriptions link each other, and the calendar event gains `Setlist playlist: <url>` once. `SpotifyApi.search_tracks` and `update_playlist_details`, `SetlistFmApi.get_setlist`.
- The weekly setlist poll, `concert-mcp poll [--force]` (a launchd job on the host runs it; a run less than seven days after the last, recorded in `<state_dir>/setlist-poll.stamp`, is a no-op). Every queued show is checked, not only the empty pages: the first run that finds songs on the setlist.fm page makes the setlist playlist, writes `Setlist playlist: <url>` into the calendar event and sends one Telegram message with the link to the topic the show was added from (else `CONCERT_MCP_CONCERTS_CHAT`); later runs top the playlist up silently as songs appear, and a row past `until` leaves the queue. `queue_status` and `concert-mcp queue` end with `Last poll: <time>`.
- The lineup (bead beads-7q9.8): after the insert, `concert_add` asks Gemini once (`gemini-2.5-flash` with Google Search grounding, 20 s cap) who opens and what set times were announced, checks the answer (an opener equal to the headliner, the venue or a ticket platform is dropped; times must parse), finds each opener's most recent setlist.fm page (`SetlistFmApi.latest_setlist`), and adds `Opener: <name>` (when the ticket named none), `Expected: doors 7:00 PM, <opener> 8:00 PM, <artist> 9:00 PM` and `Opener setlist (recent): <url>` to the event and the reply. The `lineup` tool (CLI `concert-mcp lineup`), the ninth, answers on demand and patches the topic's event. `concert-mcp gemini auth` stores the key (`<config_dir>/gemini.json`, 1Password item `Gemini - API key`); the `gemini-key` healthcheck row is `SKIP` without it, and without it everything else is unchanged.
- One event per Telegram topic (`<state_dir>/topics.json`): a repeat `concert_add` in the topic that already owns an event updates it in place (title, time, venue, description; links the new text lacks are kept) and replies `**Updated on Concerts**` with what changed, so a wrong title is fixed by replying with the right one. `another=yes` (CLI `--another`) adds a second event; `event_delete` frees the topic. `Calendar.patch_event` replaces `patch_description`.

### Changed

- Everything concert-mcp makes ends with the same line, `Created by github.com/AriSweedler/concert-mcp` (bead beads-qhcs), held once in `text/credit.py`. Every calendar event it writes (concerts, movies, plain events) now ends with it after a blank line, linked to the project's GitHub page: `to_html` adds it on the way to Google and `to_plain` drops it on the way back, so no flow reads it as a fact or writes it twice, and an existing event gains it on its next write. The Spotify teaser and setlist playlist descriptions said `Created by AriSweedler/concert-mcp` and now say the same line (unlinked: Spotify shows plain text). The Partiful description and the invite to-do are unchanged.
- A concert's calendar event reads in a fixed order (bead beads-iugd): the `Partiful:` line first, then the timing (`Doors:`, `Expected:`), then every other link line (`Tickets`, `Teaser playlist`, `setlist.fm`, `Setlist playlist`, `Venue`, ...), then the rest (`Purchased:`, `Headliner:`, `Opener:`), each group in the order it was written (`ordered_lines` in `text/topics.py`). `concert_add` writes a new or updated concert so, and `CachedCalendar` puts a recorded concert's description in order on every later patch, so an existing event is reordered on its next write. Plain events, movies and the chat reply keep their order.
- `concert_add` no longer looks the show up on setlist.fm and no longer queues it for the setlist check (bead beads-7k4): a setlist exists only after the show, and the user gives it then. The reply has no Setlist bullet, the event no `Setlist:` line, and `concert-mcp poll` only drains the shows queued before. `setlist_find`, `queue_status` and the poll are unchanged.
- The reply after a Partiful invite is made is the page and its link fields, nothing else (bead beads-p4b): the Poster bullet and the "You are marked as going; nobody is invited yet. The calendar event has the links." sentence are gone. A calendar event that could not be updated still says so.
- `concert-mcp poll` runs the whole queue every time it is called and nothing schedules it (2026-11-10): the Monday launchd job is gone from the homelab, `--force` and the "skipped: last run less than 7 days ago" report with it, and no reply promises "checking weekly for 2 months" any more. A setlist playlist is made or topped up only when asked.
- The test suite is 378 tests, down from 1270, and covers every line and every branch of the package (`pytest --cov`, `fail_under = 100` in pyproject; CI fails below it). Parametrized cases became one table-driven test each; the pure text parsers keep every case in one test per module; the flow, adapter and CLI files keep the tests that reach a line or a branch the others do not, plus every golden. Three sites are excluded with a reason: `python -m concert_mcp`, the stdio loop, and the two argparse-guarded `unknown command` raises. Along the way: `_check_mcp_sdk`, the dead placeholder check in `spotify auth` (op_read already refuses it), and an unreachable guard in `queue_list` were simplified, and the two retry loops in the Spotify and setlist.fm clients only return or raise.

### Removed

- The setlist poll, its queue and `setlist_find` (bead beads-h874): since `concert_add` stopped queueing shows, they only drained old rows, and a show's setlist now arrives only when the user gives its page (`/setlist <link>`, `setlist_playlist`). Gone: `concert-mcp poll` with its report, the `<state_dir>/setlist-poll.stamp` stamp and the Telegram message announcing a new setlist playlist; the setlist queue (`<state_dir>/setlist-queue.json`), `concert-mcp queue` and the `queue_status` tool, the delete's queue cleanup and the `setlist-queue` healthcheck row; the `setlist_find` tool and `concert-mcp setlist-find` (`--songs` included); the settings `CONCERT_MCP_SETLIST_QUEUE`, `CONCERT_MCP_SETLIST_QUEUE_DAYS` and `CONCERT_MCP_CONCERTS_CHAT`, and the queue's legacy fallback to `~/.local/state/ari-spotify/setlist-queue.json` (`concert-mcp migrate` now copies three files). The server has ten tools; the instructions no longer route "setlist alone" or "what is queued". `setlist_playlist` still finds a show's page by artist and date when it is given none.

### Fixed

- `failures collect` saves a failed screenshot that was sent with no caption (bead beads-kdn). OpenClaw writes that turn as `[Image] / Description:` with no `User text:` part, and the collect matched only the captioned form, so such a failure was never saved. Its `prompt.txt` is empty.
- `setlist_playlist` picks the version the artist originally released when Spotify has a song several times over (`Black Wave` on a K.Flay setlist landed as `Black Wave - Seattle Sessions`, the first hit; `Punisher` and `Giver` have a softer version, a remix and a session take beside the original): among the candidates that match the song and the artist, a plain title beats one with a ` - ` or parenthesised qualifier (Live, Sessions, Acoustic, Remix, softer version, Remastered…), an album beats a single beats a compilation, the earliest release date wins, and Spotify's order breaks the tie; ten candidates are read per search instead of five, and the debug line names the pick's album and year (`picked='Black Wave (Every Where Is Some Where, 2017)'`). A repeat call swaps a playlist row an earlier run filled with another version for the original, in the same slot (`SpotifyApi.replace_item`: the old track out, the new one at its position), and says so: `1 swapped for the original version: Black Wave`; the poll's row reads `12 songs; 1 swapped`. A dry run swaps nothing.
- `setlist_playlist` finds released songs the `track:<name> artist:<artist>` search missed (ten of eighteen on a K.Flay setlist, among them songs on her albums): when that search returns nothing by the artist, a plain `<name> <artist>` search follows and its candidates are matched by loose name (case, accents and punctuation ignored, so a curly apostrophe or `K.Flay` against `K Flay` no longer loses a match) and by the artist's Spotify id or loose name; a candidate by another artist is never added, so a wrong-artist first hit no longer lands in the playlist. `--log-level debug` logs each song's query and candidates. A repeat call tops the playlist up with the songs now found.
- The `Purchased:` line takes the amount after a receipt's `TOTAL` label (not `SUBTOTAL`), else the largest amount; the count also reads `1 General Admission`, `Qty: 2` and `2 x $20.00`.
- `concert_add` asks the user for the headliner when the artist is a ticket platform (`DICE`, `Ticketweb`, ...) or the venue, and drops a caller-named opener the source text does not contain.

## [0.1.0] - 2026-10-25

The first release extracts the concert stack from three dotfiles scripts (`cal-add.py`, `cal-del.py`, `spotify.py`) into one package. Every reply string, FIX text, record key, path default and guard those scripts implemented is carried over; the deliberate wording changes are listed under Changed and mirror `docs/DESIGN.md` §10.

### Added

- The `concert_mcp` package: `text/` (pure parsing and rendering), `adapters/` (gws, Spotify, setlist.fm, OpenClaw, 1Password, state, clock behind Protocols), `flows/` (the policy, returning `Outcome`), `server.py` and `cli.py`.
- The seven MCP tools over stdio: `concert_add`, `calendar_add`, `event_delete` (with a `pick` parameter), `teaser_playlist`, `setlist_find`, `queue_status`, `healthcheck`. Every parameter is a `Param`: a string with a default of `""` whose validator cleans a number, a null or a quoted value before pydantic sees it, so the model never gets a schema error; the server's instructions carry the NO_REPLY / FIX rules; `event_delete` is annotated destructive and the three lookups read-only. The documented OpenClaw entry filters the model's view to `concert_add`, `calendar_add` and `event_delete`.
- The `concert-mcp` CLI with the same flows: `serve`, `add`, `del` (alias `delete`), `teaser`, `setlist-find`, `queue`, `healthcheck`, `config`, `migrate` and the `spotify` subcommands (`auth`, `me`, `liked`, `playlists`, `playlist-tracks`, `playlist-create`, `playlist-add`, `rename`, `playlist-unfollow`, `search-artist`, `setlist-auth`); global `--json`, `--dry-run`, `--no-send`, `--config-dir`, `--log-level`.
- `concert-mcp healthcheck`: one `PASS/FAIL/SKIP` row per credential and tool (17 checks), a README anchor per failure, exit code equal to the number of failures, `--probe` for one real call per provider, `--only NAME` to run a subset. It is read-only (an absent directory under a writable parent is `PASS ... absent (created on first write)`); a locked-keychain failure of `gws-auth` prescribes the file keyring key, not a login, and `concerts-calendar` is then `SKIP gws-auth failed`.
- `concert-mcp migrate`: copies the four `ari-spotify` files to the `concert-mcp` paths, never deletes, mode 600 for credentials, `--dry-run` reports `would copy`. The legacy paths are read as a fallback until the new files exist.
- `fix_guard`: the third `FIX:` for one tool within 15 minutes becomes a reply asking the user for the details in one line, worded per tool for `concert_add`, `calendar_add` and `event_delete`.
- A date-only `start` is accepted for a concert when the ticket text states the show time (`Start taken from the text (8:30 PM).`).
- A bare number as the `title` of `event_delete` means `pick`, when a candidates list exists. A list older than `CONCERT_MCP_CONTEXT_WINDOW_S` (15 minutes) is removed and answered with `I do not have a list to pick from any more ...`, for `pick` and the bare number alike.
- `clean_param`: tool arguments are squashed, one pair of matching quotes is stripped, and `null`, `None`, `n/a` and `undefined` become empty.
- Two no-space time formats, `2026-11-14 8:30PM` and `2026-11-14 8PM`, beside the six legacy formats.
- Settings from `CONCERT_MCP_*` environment variables over `<config_dir>/config.toml` over defaults, XDG-aware; `concert-mcp config` prints the effective, redacted table. `gws` and `openclaw` are searched on PATH, then in `/opt/homebrew/bin`, `/usr/local/bin` and `~/.local/bin` (a launchd-started gateway has a bare PATH); the healthcheck's `*-binary` rows name `CONCERT_MCP_GWS_BIN` / `CONCERT_MCP_OPENCLAW_BIN` when both miss.
- The server reads the Spotify and setlist.fm credential files lazily, so `concert-mcp spotify auth` or `setlist-auth` run while the gateway is up takes effect on the next call without a restart.
- The Spotify teaser cap (`CONCERT_MCP_TEASER_TIMEOUT_S`) covers the whole step: every paged read carries the deadline and the playlist create and add are skipped past it (`not made (Spotify took longer than 150 s)`).
- `--log-level debug` logs every subprocess argv with a secret argument shown as `<redacted>`; `op item edit ... "refresh token[password]=..."` is logged without the token. Credential files are created with mode 600 from the start, never 644 and then chmod-ed.
- A crash inside a tool becomes the reply `Something broke inside the concert tool (<Type>). <operator>: check the gateway log.` instead of an MCP error.
- Tests on fakes for every layer, a stdio smoke test, a docs test (`tests/test_readme.py`, which also scans every text file in the repository for personal data: emails, Telegram chat ids and bot tokens, Google calendar ids, `.local` hostnames) and a grep that keeps `print()` out of the library. Every example and fixture is fictional (`Zed Fox`, `The Quarry`, `ZZZ Bistro`).
- `docs/DESIGN.md`, `docs/migration.md`, `docs/homelab-integration.md`, `CONTRIBUTING.md`, a bug-report template, `.python-version` (3.12), GitHub Actions CI (lint, tests on 3.11 to 3.13, a bare-box healthcheck, the personal-data scan as its own job).

### Changed

- `Ari:` → `{operator}:` (`CONCERT_MCP_OPERATOR_NAME`, default `Admin`); `on the laptop` → `on the host`; `The laptop keychain` → `The login keychain`; the locked-keychain reply ends `{operator}: create the gws file keyring key (README.md#google-calendar) or run this from a session with keychain access.` instead of naming a tmux pane.
- The inferred-show-time FIX is literal: `set start to "2026-11-14 8:30 PM" (the show time in the text; 7:30 PM is doors)` instead of `the text puts the show at 8:30 PM (doors are earlier); use that`, so the model copies a value rather than composing one.
- A plain (`calendar_add`) event no longer runs the ticket parsers over the live context: no show-time check, no derived Doors/Purchased/Opener lines, and a title such as `[Dinner] Team dinner with Sam` is kept whole instead of being split at `with`. The hallucination filter still drops a caller line whose URL, price or clock time is not in the text. (The legacy ran every parser for every event, but its DM flow never shared a context window with a ticket.)
- The standalone `setlist_find` reply drops `; checking weekly for 2 months`, which only `concert_add` (the one that queues the show) may promise.
- `openclaw message send` gets 20 s per try instead of 60 and no pause after the last failed try; the documented `requestTimeoutMs` is 480000 (typical call 60–150 s, worst case about 8 min).
- A setlist-queue write that fails after the event was inserted is the note `Not queued for the setlist check: <Type>` on the reply instead of a crash without the calendar link.
- Teaser `not made (ari-spotify skill is not on this machine)` → `not made (Spotify is not set up: run \`concert-mcp spotify auth\`)`; the Spotify failure text is `str(ProviderError)[:160]` instead of the last stderr line (same content, no ANSI).
- Setlist: a missing setlist.fm key yields `lookup skipped (setlist.fm is not set up: …)` instead of silently omitting the bullet (the legacy only omitted it when the whole skill was absent).
- Teaser description: `every song Ari liked by them, in the order he liked them` → `every liked song by them, in the order they were liked`.
- `on Concerts and Personal` / `on Concerts or Personal` use the configured calendar names.
- FIX lines on the MCP path gain ` Call <tool> once more with only that change.`; the CLI prints the legacy line.
- New, additive: `clean_param`, bare-number title as pick, date-only start from the ticket text, two no-space time formats, `fix_guard`, `queue_status`, `healthcheck`, `calendar_add` as a named tool.
- The setlist.fm `User-Agent` is `concert-mcp/<version> (personal concert bot)`; the 1Password item default is `Spotify - concert-mcp`.
- The delete candidates list and the reply dedupe log moved from `~/.openclaw/media` to the state directory (`delete-candidates.json`, `last-sent.json`); both expire within minutes, so there is no fallback.

### Removed

- Shelling out to `spotify.zsh` for the teaser and the setlist lookup; both are in-process `urllib` clients now, and their failures are exceptions the flow turns into reply bullets.
- Module globals (`JSON_MODE`, `SEND`, the hard-coded `HOME`-relative paths); everything is a frozen `Settings` passed in.
- `sys.exit` and `die()` in library code; only `cli.py` exits, and only `cli.py` and `flows/auth.py` print.
